### 7.3 Physical performance acceptance — proposed numbers and calculation method

**Baseline proposal:** fixed reference quality, actual 1920 × 1080 render buffer, render scale 1, declared antialiasing/shadows/reflection/texture settings, no hidden dynamic resolution, camera change, density change or Auto quality adjustment. Auto backend selection may be smoke-tested separately; forced backend runs never fall back. A lower quality or 30 FPS alternative would require explicit approval and is **not the current baseline**.

**For each forced backend on the same candidate/hardware/settings:**

- Capture one cache-cleared **cold run** (HTTP browser cache disabled/cleared as documented; do not call it an OS-disk/shader-cache reset). Separate request/transfer, decode/transcode, GPU upload/compile where observable and first usable frame. Record the first traversal's stalls even if excluded from the warm score. Local production-server tests do not establish WAN/CDN download speed; hosted runs record network/cache conditions separately.
- Perform **30 s warm-up**, then **three 60 s scored route runs**; record all three separately, no cherry-picking. Record first/subsequent runs and any deliberate shader warm-up.
- Perform **one 15-minute sustained loop per supported backend** after the warm tests, same fixed settings; keep start/end resource counts and 60 s block summaries. This is a proposed bounded stability run, not a laptop lifetime guarantee.
- Export consecutive foreground `requestAnimationFrame` timestamps/intervals, sample count, settings/hashes/backend/resolution, route position/time and loading/error markers. These are **browser frame-pacing proxies**, not scanout/presentation latency or GPU frame time. Record CPU/GPU timing only if measured with documented supported tools/queries; no fake timing when disjoint/unavailable.
- Calculate interval distribution using **nearest-rank percentiles** (`sorted[ceil(p × N) − 1]`), median defined consistently at p=0.5, and average FPS `1000 × N / sum(interval_ms)`. Count intervals >50 ms and >100 ms separately. Do not average per-frame reciprocal FPS. Keep stalls in the warm data; only explicitly separate the cold/warm phases. Background/occlusion/sleep/resize or buffer/settings changes invalidate a scored run—retain it and state the reason for a replacement, not silently discard it.

| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **60-class pacing**            | **Each** 60 s warm run: average ≥ **59.0 FPS**, median ≤ **16.9 ms**, p95 ≤ **20.0 ms**, p99 ≤ **33.4 ms**. The 59.0/16.9 tolerances acknowledge timing/vsync measurement near 60 Hz; this is an explicit proposed operational definition of the 60 FPS aspiration, **not permission to silently lower it**.
